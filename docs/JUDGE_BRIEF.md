# RETCON — hackathon brief

**Pitch:** Every data engineer knows backfill. Novelists call it retcon.

**Writer promise:** Change a character's fate, inspect the consequences, and approve only the needed repairs.

## Why it stands out

RETCON makes a story revision visible as a data workflow. The demo distinguishes three dependent chapters from two actual contradictions, preserves the valid memory chapter, and shows a small diff before the author publishes.

| Judging dimension | Demonstrated feature |
| --- | --- |
| Creativity | Story continuity expressed as dependency checking and selective repair |
| Airflow usage | Plugin UI/API, packaged DAG bundle, Assets, dynamic mapping, Common AI, native HITL |
| Usefulness | Draft import, chapter editing, quoted findings, diffs, approval, export |
| Demo | “Kill a character, watch the consequences” with readable evidence |
| Implementation | Validated model output, bounded retries, atomic publication, 131 passing tests |

## Positioning

Story bibles and contextual writing already exist in tools such as [Novelcrafter](https://www.novelcrafter.com/features/codex), [Sudowrite](https://docs.sudowrite.com/using-sudowrite/1ow1qkGqof9rtcyGnrWUBS/chapter-continuity/4KL8gFeLZQ6GSBjDWtSbV6), and [Plottr](https://docs.plottr.com/article/54-timeline-overview). RETCON's focus is an explicit change workflow: inspect impact, check existing text, repair selectively, and obtain author approval.

Target users are serial-fiction writers, editors, and narrative-game teams. Commercial demand is unvalidated; the demo demonstrates the workflow, not a market-size or revenue claim.
